## Full-text search (built, waiting for the owner's check)
Memo: `docs/design/research/search.md`; decision 64. Four reviewers ran and their findings were fixed.
- **What it is:** Ctrl K (or the dashboard search bar) now searches your tasks and tags next to the commands. Every typed word matches the start of a word in the title or description ("pay re" finds "Pay rent"). Results come in groups Tasks and Tags with highlighted matches, a short snippet when the match is in the description, Done / Archived / due-day labels, and "Recent" (last 5 opened) on an empty field. Enter opens the task in My tasks (or filters by the tag).
- **Migration to apply:** `0010_tasks_search_vector.sql` (triggers on tasks that fill `entities.search_vector`, plus a backfill of existing tasks; the backfill refreshes `entities.updated_at` once). After `pnpm db:migrate`, check in Supabase: the functions `task_search_vector` and the triggers `tasks_search_vector_insert` / `_update`, and `select count(*) from entities where type='task' and search_vector is not null`.
- **Server:** `POST /search` (read action `search.global`), `UserScope.selectFields`, `apps/server/src/lib/search.ts` (the only full-text SQL).
- **Decisions to review:** a task is not found by its tag name (open the Tags result instead); only word starts match (no typos, no mid-word, no accents); POST instead of the GET in the old API.md; recent items stay on this device (cleared on sign-out).
- **Known limits:** snippet is not shown when the words are split between title and description; marks in the app follow a simple letters/digits rule that can differ slightly from Postgres for words like "invoice-42".
- **Manual test:** apply 0010, restart server and app; Ctrl K, type "pa" (a task appears under Tasks), type "pay re"; check the highlight in dark and light; press Enter (task opens in the panel); search an archived and a done task; type a tag name start (Tags group, Enter filters); type one letter (only commands); stop the server and search (commands still work, quiet error row); empty field shows Recent; test the speed in the browser network tab (should be well under 1 s).

## Realtime updates (built, waiting for the owner's check)
Memo: `docs/design/research/realtime.md`. Reviewed; the findings are fixed (a change that never finishes saving no longer holds updates back for more than about 3 seconds).
- **What it is:** changes made elsewhere (the AI later, another window, the Supabase table editor) show up in the app by themselves within about a second. The app listens to Supabase Realtime for tasks, tags, task tags, favorites, links and goals; an event only tells it which table changed, then it reloads what is on screen (batched every 300 ms, never over a change you are still saving). After a reconnect it refreshes everything. Settings → Account has a read-only "Live updates" row (On / Connecting… / Reconnecting… / Off). The window-focus refresh and the 15 s stale time stay as a safety net.
- **Migration to apply:** `0011_realtime_publication.sql` (adds the six tables to the `supabase_realtime` publication, `GRANT SELECT` to `authenticated`, `REVOKE ALL` from `anon`). Check in Supabase: `select tablename from pg_publication_tables where pubname = 'supabase_realtime';` lists tasks, tags, entity_tags, task_favorites, links, goals; `information_schema.role_table_grants` shows SELECT for authenticated and nothing for anon; 12 rows in `drizzle.__drizzle_migrations` after 0011.
- **Not verified (needs the real Supabase):** whether a rejoin after sleep sends SUBSCRIBED again (manual test 6 in the memo); a status stuck on "Reconnecting…" means the grants or the token need checking.
- **Known limit:** authenticated users may still have write grants on older tables (a stolen token could write through Supabase's own API and skip the action registry); the memo suggests a later migration that keeps only SELECT.
- **Manual test:** apply 0011, restart the app; Settings → Account shows "Live updates: On"; edit a task title in the Supabase table editor and watch it change in My tasks; open http://localhost:1420 in Chrome as a second window and add, complete, tag and favorite things; turn Wi-Fi off (Reconnecting…) and on (On); sign out (Off).
