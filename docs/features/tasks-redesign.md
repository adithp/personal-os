# Tasks redesign (Step 2): layout, build plan, and file ownership

This is the approved plan for the Tasks module redesign (Asana-style, dark glass, minimal). Liquid Glass is not part of it. The parallel-agent rules are in CLAUDE.md ("Parallel work").

## Status
- Feature 1 is built (side panel, Overview, My tasks Cards and List, detail panel, subtasks, tags, archive); Repeat and Blocked by were placeholders then and are real since Feature 3.
- Feature 2 is built (Board view; drag and drop in Cards, List and Board; the tasks.move action). Feature 3 is built (dependencies and recurring tasks, with the Repeat and Blocked by rows). Feature 4 is built (the quick-add bar understands dates, tags, priority and repeats). Feature 5 is built (favorites in the side panel and on Overview, and the Manage tags dialog). Feature 6 (Inbox) and Feature 7 (Reporting) are built. Feature 8 is not started (Goals shows a "Coming soon" page).
- @dnd-kit (core, sortable, utilities) is installed (Feature 2); rrule 2.8.1 (server, Feature 3) and chrono-node 2.10.2 (desktop, Feature 4) and recharts 3.10.1 (desktop, Feature 7) are installed.

## Screens
- **Inner side panel** (inside the Tasks page; the bottom dock stays the main navigation): Overview, My tasks, Inbox (count), Reporting, Goals, Portfolios (disabled, "Soon", Step 5), and a Favorites list with a + button. Collapsible. Goals is disabled with "Soon" until its feature is built (`modules/tasks/features.ts`).
- **Panel details:** 224 px wide with labels, or 56 px with icons and tooltips when collapsed (the choice is saved). A disabled row shows "Soon". The Inbox count rules are in docs/features/tasks.md (Inbox).
- **Overview** (opens from the dock and Ctrl 2): greeting with the date and "7 open · 2 overdue", a collapsible "Tasks due soon" card (5 open tasks, overdue first, then today, then upcoming), and a Favorites section (at most 6 tiles; hidden while there are no favorites).
- **My tasks**: header with Cards (default) | List | Board (saved on this device), Filter / Sort / Group, a quick add bar. Sections: Overdue, Today, Upcoming, No date, Completed (collapsed, last 7 days, "Show more"). Defaults: Group = due, Sort = manual. Overdue is by India calendar day. When Sort is not manual, drag-to-reorder is off with a hint.
- **My tasks details:** the summary reads "N open · M overdue" ("Nothing left to do" when none). Filter menu: Status (To do, In progress, Done), Priority, Tag, Due (Any, Overdue, Today, This week, No date), Archived; "Clear filters" appears when any filter is on. Sort: Manual (default), Due date, Priority, Created, Title. Group: Due (default), None, Tag (a task appears in each of its tags, untagged under "No tag"), Priority. Filters, sort, group, and the open task can be in the URL (status, priority, tag, due, archived, sort, group, task). When Sort is not Manual a quiet hint says reordering is off.
- **Detail panel** on the right: status, priority, due (date, time, or all-day), reminder, repeat, tags, blocked by, subtasks (one level), notes, Archive, Delete.

## Decisions (answers recorded)
- Due dates may be all-day: `tasks.due_all_day` (default false); an all-day task stores the start of that day in India time and shows the date only. Dropping on Today keeps an existing time, otherwise makes it all-day.
- Subtasks appear only inside their parent. Completing all subtasks does not complete the parent.
- Tags: auto color from the module palette in a cycle; recolor from a chip's menu; a card shows the first tag plus "+N".
- Favorites are stored on the server (`task_favorites`, Feature 5). Goals use the `links` table with a new `goal` entity type (Feature 8).
- Saved on this device (localStorage key personal-os.tasks-ui): the view, whether the side panel is collapsed, and which date sections are collapsed. Sort, group, and the open task start fresh.
- Keyboard (only on the Tasks page, not in a text box, no Ctrl combinations; the Inbox adds T, L and 1 to 4, see docs/features/tasks.md; Space and Enter act on the focused card or row; none of the keys work while the palette is open, in menus or dialogs, or inside the detail panel): N new task, Space complete, Enter open details, Delete delete (undo toast), Esc close, arrows move, ? shortcut help. On a drag handle the keys belong to dragging (Space lifts and drops, arrows move, Esc cancels) and the page shortcuts are ignored.

## Feature 2 contract (committed before the agents start)
`tasks.move` (shared `moveTaskInput`: `status`, `dueAt`, `dueAllDay`, `afterId`, `beforeId`) is built (server: position between the neighbours, rebalance, same path as tasks.update); `tasks.update` now also accepts `position`, and `applyChange` in `actions/tasks.ts` is exported for the move to reuse. On the desktop: `modules/tasks/drag/` has `position.ts` (positionBetween), `resolve-drop.ts` (resolveDrop: Today keeps a time or makes the task all-day, Upcoming asks for a date, Overdue refuses, No date only reorders, Completed completes, a done task dragged out reopens; reordering needs Manual sort), `drop-ids.ts`, and `dnd.ts` (sensors and spoken announcements); `shared/drag-handle.tsx`; `useTaskActions().move`; and the mock API route. `TaskCard` and `TaskRow` take an optional `drag` prop (ref, style, handle) and `BoardView` gets a `manualSort` prop. The Board is on (`TASK_FEATURES.board`). Drop rules (`resolveDrop`) are listed in docs/features/tasks.md. Decisions made while building: a drop on No date from another section is refused with a message; the Upcoming date picker starts on tomorrow; with Sort not Manual the neighbours are not sent (only the section or status changes); the Board insertion shows a line and does not shift cards; the dashboard tile "Today's tasks" now shows real tasks (the rest of the dashboard is still placeholder data).

## Feature 3 contract (committed before the agents start)
`packages/shared/src/recurrence.ts` has the repeat presets (`buildRecurrence`, `parseRecurrence`, `describeRecurrence`, `recurrenceRuleSchema`); `recurrenceRule` is accepted by create and update (a repeating task needs a due date). New actions `tasks.addBlocker`, `tasks.removeBlocker` and `tasks.reopen` (the undo of completing a repeating task: it restores the old values and removes the copy that completing it created, decision 47); routes `POST /tasks/:id/blockers` and `DELETE /tasks/:id/blockers/:blockerId`. The server files `actions/task-dependencies.ts` (loadBlockers, assertNotBlocked, the two blocker actions) and `actions/recurrence.ts` (spawnNextOccurrence, tasks.reopen) are implemented (Feature 3). On the desktop `useTaskActions()` has `addBlocker` and `removeBlocker`, and the mock API follows the blocker rules.

## Feature 4 contract (committed before the agents start)
`tasks.create` accepts `tagNames` (find or create by name). `modules/tasks/quick-add/parse.ts` has the types and the signature `parseQuickAdd(input, now, ignored)` (implemented in `parse.ts`, `parse-date.ts` for chrono and `parse-repeat.ts`): it returns the title, `dueAt`/`dueAllDay`, `priority`, `tagNames`, `recurrenceRule` and the list of understood `parts` (each with kind, typed text, position and a label for the chip); `partKey` names a part so the bar can switch it off. The mock API's create route handles `tagNames`. `chrono-node` 2.10.2 is installed in apps/desktop.

## Feature 5 known limits
- Writes to favorites and tag deletes/merges are queued per user inside the server process (not a database lock), which is enough for one server instance; several instances would need a lock helper in `UserScope`.
- The tag usage counts in `tags.list` are counted in code, not with a SQL group-by (fine for one user).
- The favorites links are all Tab stops (decision D12), 12 at most; the Overview tile is built by hand from the Tile rules (not the shared `Tile`); menus do not follow a scroll while open.
- Undoing a merge does not remove the target tag from the tasks, and an undo is not offered above 5000 tasks.
